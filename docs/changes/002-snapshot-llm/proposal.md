# 002: Snapshot loader, path-jailed tools, and LLMClient (M2)

## What

- `internal/snapshot` opens the mounted snapshot directory, reads the optional `project.json` (name, starter questions, overview files, sessions directory), builds the cached overview (tree, session index, spec and decisions log), and serves the three read-only tools: `list_files`, `search_files`, and `read_file`.
- `internal/llm` defines the `Provider` and `Conversation` interfaces, with OpenAI (`gpt-6-luna`, Responses API) and Anthropic (`claude-haiku-5-5`, Messages API with prompt caching) implementations.
- `internal/agent` runs the tool loop with the step cap. The standing instructions live in `prompts/system.md`.
- `internal/chat` and two protected routes: `POST /api/chat` (JSON, one question per request) and `GET /api/starters`. Chat limits, one conversation per session, and the question log (`internal/questionlog`, secrets masked).
- `cmd/compare` runs the same questions against both providers and writes a Markdown report.
- A fixture snapshot, `evaluation/fixtures/tiny-kv`, and a question list, `evaluation/questions.txt`.

## Why

Interviewers need answers about the code and the approach, grounded in the snapshot (R4, R6). The model must only read the snapshot, through a jail it can't talk its way out of, and must stop after a bounded number of tool calls (R5). The runtime reads a plain directory so ingestion can change later without touching it (R7). Starter questions come from the snapshot and questions are logged for debrief prep (R11). Two providers behind one interface let Josh compare them (S-D9).

Requirements: R4, R5, R6, R7, R11 (loader and question log; the UI is M3), R10 (chat limits), S-D2, S-D9, S-D11.

## Decisions

| ID | Decision | Rationale | Decided by |
| --- | --- | --- | --- |
| 002-D1 | The jail has two layers. Model-supplied paths are cleaned and rejected if absolute, `..`-escaping, or containing NUL or backslashes. Then each path component is checked with `Lstat` through Go's `os.Root`, and any symlink makes the path unavailable, even one that stays inside the snapshot. Symlinks are left out of listings, searches, the tree, and the session index, and a symlinked `project.json` stops startup. Names that look like VCS internals or secrets (`.git`, `.env`, `.envrc`, `.env.*`, `.env-*`, `.env_*`, `.ssh`, `id_rsa*`, `*.pem`, `*.key`, `*.tfvars`, `credentials.json`, and similar) are hidden from every tool and from the overview. | An inside link such as `docs/notes.md -> ../.env` would otherwise expose a hidden file, and `rsync -a` and `scp -r` keep links (review on PR #3). Refusing all symlinks is simpler than resolving them and re-checking. | Claude (for review) |
| 002-D2 | `project.json` is optional: `name`, `starter_questions`, `overview_files`, `sessions_dir`. Without it, well-known names (`README.md`, `SCOPING.md`, `docs/spec.md`, `docs/decisions-log.md`, and others) and `sessions/` or `docs/sessions/` are used. A malformed `project.json` stops startup. The overview is built once at startup; after updating a snapshot, restart the container. | Works with zero config but lets a project choose what goes in the cached prompt. A fixed overview keeps the prompt cache valid. | Claude (for review) |
| 002-D3 | Both providers use small hand-written `net/http` clients, with no SDK dependency. JSON shapes follow the official SDKs and API reference: OpenAI Responses (`store: false`, encrypted reasoning passed back) and Anthropic Messages (`x-api-key`, `anthropic-version: 2026-10-21`, reply content stored byte-for-byte so thinking blocks go back unchanged). | The official OpenAI Go SDK couldn't compile on the VPS (out of memory). With the Anthropic SDK, a cold build peaked at about 2.5 GB in the build container, and a cold image build took host usage to 3752 of 3814 MB. Without SDKs, a cold build peaks at 383 MB and takes 50 s instead of 151 s; see results. | Josh (no SDKs), Claude (implementation) |
| 002-D4 | Each session has one conversation, kept in the provider's own message format and only ever appended to, in memory. It is dropped on logout, after `SESSION_TTL` idle, or on restart. Before each question, if the last model call's input tokens plus a worst-case estimate for one question (`(TOOL_STEP_CAP × TOOL_OUTPUT_MAX_CHARS + MAX_MESSAGE_CHARS) / 3`, about 40k tokens with defaults) would exceed `CONTEXT_MAX_INPUT_TOKENS` (default 100k), the session starts a fresh conversation and the response says `conversation_reset: true`. If a provider still rejects the input as too long, the question is retried once in a fresh conversation; if that fails too, the error is `conversation_full`. | Rewriting history would invalidate prompt caches and, on Haiku 5.5, the model's earlier thinking, so the conversation is replaced rather than trimmed. 100k keeps Haiku 5.5 in its cheaper price band (prompts up to 100k tokens) and well under both models' windows. Without the limit, a long session would hit the context window and fail every later question (review on PR #3). | Claude (for review) |
| 002-D5 | The step cap counts individual tool calls, including parallel ones. Calls past the cap get an error result ("limit reached, answer now"), then one final model call with tools disabled. If the model still calls a tool, a fixed fallback answer is returned. A question costs at most `TOOL_STEP_CAP + 1` model calls. | Every tool call gets a result, so the conversation stays valid for the next question. The bound on cost is exact. | Claude (for review) |
| 002-D6 | Tool contracts: `list_files` lists one level (up to 500 entries); `search_files` is a literal, case-insensitive line search (up to 50 matches; skips binary files and files over 1 MB); `read_file` returns numbered lines with optional `start_line`/`end_line`, refuses binary files and files over 4 MB, and cuts long output at a line boundary with a note saying where to continue. Every result is capped at `TOOL_OUTPUT_MAX_CHARS`. | Line numbers make exact citations possible (R6). Literal search can't be abused with expensive patterns. The caps bound token cost per step. | Claude (for review) |
| 002-D7 | The standing instructions live in `prompts/system.md`, embedded in the binary. The prompt version is the first 12 hex digits of its SHA-256, logged with every question and printed in each comparison report. | Prompts change as plain-text diffs, and every answer can be traced to the prompt that produced it. | Claude (for review) |
| 002-D8 | The question log is JSON Lines in `DATA_DIR/questions.jsonl` (mode 0600): time, email, provider, model, prompt version, the question (masked), tool and model call counts, sources, tokens, latency, and any error. Answers are not logged. Masking covers configured secret values, API-key and token shapes, long opaque strings, and 6-digit numbers. The server log records turn metrics but not question text. | Enough for debrief prep (S-D6) without storing answers. A pasted magic code or key never reaches disk (R3). | Claude (for review) |
| 002-D9 | M2 serves chat as plain JSON: `POST /api/chat` returns the answer, sources, tool steps, and remaining turns. M3 adds SSE streaming and the UI on top of the same service; the agent already reports each tool step through a callback. A turn is counted once a request passes validation and rate limits, before the model is called, so failed model calls still use a turn. One question at a time per session (`409 busy`). | Makes R4 testable end to end now without building the UI twice. Counting before the call keeps the turn cap a hard bound on spend. | Josh |
| 002-D10 | Models run with their own reasoning and thinking defaults (Haiku 5.5 uses adaptive thinking at medium effort; nothing is set for `gpt-6-luna`). OpenAI requests set `store: false` and ask for encrypted reasoning so it can be passed back. New settings: `LLM_MAX_OUTPUT_TOKENS` (16000), `LLM_TIMEOUT` (120s per model call), `TOOL_OUTPUT_MAX_CHARS` (20000), `OVERVIEW_MAX_CHARS` (60000). Both clients retry 429 and 5xx (including Anthropic's 529 "overloaded"), and connection errors from before the request was sent, up to twice, honouring `Retry-After` up to 10 seconds (see 002-D12). | Provider defaults are the sensible starting point until the comparison shows otherwise. `store: false` keeps conversations off OpenAI's servers. Short retries ride out brief overloads; the turn cap and step cap still bound spend, because a retry repeats the same model call rather than starting a new one. | Claude (for review) |
| 002-D11 | The overview sits inside `<snapshot_overview>` and `</snapshot_overview>` in the system prompt. `prompts/system.md` says everything inside them, and every tool result, is untrusted project data. Copies of the tag inside snapshot text are replaced with `[tag removed]`, so a file can't close the block early. | Snapshot text sits in the most trusted position, and a README heading such as `## Safety` would otherwise look like one of our own rules (review on PR #3). | Claude (for review) |
| 002-D12 | Timeouts: once a request has been sent, a timeout or broken connection is not retried, because the provider may already have generated and billed the reply. Only failures before sending (dial, TLS, connection refused) are retried. A whole question is bounded by `QUESTION_TIMEOUT` (default 3m), which also frees the session lock. | Without these, a slow call could be billed three times, and one question could run for over 40 minutes while holding the session (review on PR #3). | Claude (for review) |
